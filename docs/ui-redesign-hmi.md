# 面板 UI 改造：工业设备 HMI 风（方案 D）

> 分支 `ui-redesign`（从 `f3af5f8` 切出）。目标：四页换皮为工业设备 HMI 风格，
> **信息架构、数据口径、四页划分全部不变**。
>
> 效果图：`~/Desktop/panel-ui-mockups/D-工业设备HMI.png`（480×480，PIL 渲染，像素精确）

## 一、设计规格

### 配色（`ui_theme.h`）

| 名称 | 值 | 用途 |
|---|---|---|
| `COL_BEZEL` | `#3a4046` | 外层金属框 |
| `COL_BEZEL_LT` | `#4e565d` | 框体高光边（上/左） |
| `COL_BG` | `#1a1e21` | 屏内底色（原为 `#0f1418`，改暖一点） |
| `COL_BOX` | `#21262a` | 盒子填充（原 `COL_PANEL`） |
| `COL_BOX_EDGE` | `#5c656e` | 盒子边框（工业风边框要比现在**明显**） |
| `COL_BAR` | `#14171a` | 顶栏/状态栏底色 |
| `COL_TEXT` | `#ced6dd` | 正文 |
| `COL_LABEL` | `#96a2ad` | 盒子标题文字 |
| `COL_DIM` | `#808b95` | 次要文字 |
| `COL_AMBER` | `#ffb03c` | 磷光琥珀：主读数 / 告警 |
| `COL_GREEN` | `#7ae27a` | 磷光绿：正常 / 正向趋势 |
| `COL_RED` | `#ff5c52` | 异常 |

**关键变化**：现在的主题是「暗蓝底 + 薄荷青强调」，工业风要改成「炭灰金属 + 琥珀/绿磷光」——
**薄荷青 `#2dd4bf` 全部弃用**，强调色改用琥珀与磷光绿。这一步会连带影响四页所有着色逻辑。

### 几何

```
外框 bezel      3px 金属边 + 1px 高光边，内屏内缩 10px
顶栏            高 28px：设备标识 + PWR/NET/ALM 三个 LED + 刷新按键
状态行          高 ~18px
三格读数盒      y 66..160（高 94px），宽 =(屏宽-16-16)/3 ≈ 142px
平台/国家两列   y 178..372，左右各半
底部三格        y 388..464（高 76px）
```

**盒子标题占盒子上方 6px** —— 这是本轮最容易被忽略的一处：
`titled_box` 的标题压在边框线上，其不透明底色「切断」边框。若不留这 6px，
标题会压到上一个盒子的内容（第一版效果图就踩了这个，三格底部的「金额」被切掉）。

### 组件（`ui_theme.h` 提供内联 helper）

| 组件 | 实现要点 |
|---|---|
| `ui_titled_box(parent, title)` | `lv_obj` + 明显边框；标题 label 定位于盒子左上、y 偏移 -6，并设**不透明底色 = 盒子填充色**以切断边框 |
| `ui_led(parent, color)` | 小 `lv_obj`，`radius=50%`，填充彩色；外圈用 `border` 画暗灰环 |
| `ui_bevel_button(parent, label)` | `lv_obj` + `bg_grad_dir=VER`（上亮下暗模拟斜面）+ 1px 深色外框 |
| `ui_dotted_leader(...)` | ⚠️ **降级实现**，见下 |

## 二、LVGL 可实现性（务必先读，别照抄效果图）

效果图是我用 PIL 画的，画得很轻松的东西在 LVGL 里未必现成：

| 效果图元素 | LVGL 可行性 | 处理 |
|---|---|---|
| 带标题边框盒 | ✅ **好做** | 容器边框 + 标题 label 带不透明底色即可 |
| LED 状态灯 | ✅ **好做** | 小圆形 `lv_obj` + 边框环 |
| 金属 bezel | ✅ **好做** | 外层容器边框 + 内层内缩 |
| 立体按键 | 🟡 **近似** | LVGL 边框四边同色，做不出「上亮下暗」；用 `bg_grad_dir` 垂直渐变近似 |
| **磷光辉光** | ❌ **做不出** | LVGL 无文字发光。**决定：放弃辉光**，或用偏移 1px 的暗色副本 label 近似（每格多一个对象，可选） |
| **点线引导符** | ❌ **做不出** | LVGL 无虚线/点线。**决定：改用 1px 实线 + 低亮度**（观感接近，成本为零） |
| 等宽数字读数 | 🟡 **需新字库** | 见下 |

**结论：观感能拿到效果图的约八成，代价可接受。辉光与点线是明确放弃的两项。**

## 三、字库（本方案唯一的新增资产）

效果图的大读数是 34px 等宽磷光数字。现有字库不够：

| 字库 | 现状 | 是否够用 |
|---|---|---|
| `font_sm`（16px） | 完整 6887 GB2312 | ✅ 小字全部够用 |
| `font_lg`（20px） | ~401 字子集（扫描 `business/ui/*.c` 生成） | ✅ 够用，但**新文案若走 20px 需重新扫描生成** |
| 大数字读数 | 无 | ❌ **需新增** |

**新增 `font_num`（建议 34px）**：只包含 `0123456789.,%¥-+ /` 与少量单位字
（件/单/万/亿/天/时/分），子集极小 → **flash 成本可忽略**。
路径：`firmware/main/fonts/font_num.c`，用同样的字库生成流程（见 `fonts/` 下现有脚本）。

> 备选：启用 LVGL 自带 Montserrat 34（`LV_FONT_MONTSERRAT_34`）—— 但它没有中文单位字，
> 且完整拉丁字库比子集大得多。**不推荐。**

## 五、必须守住的约束

- **不能回归数据逻辑**。页面只负责显示；`panel_snapshot_t`、`ops_usable`、
  业务自然日、`stale_reason` 等全部不动。
- **`ui_set_label_cached` 的缓存必须 ≥ 文案长度**。该函数用 `strcmp` 去重，
  缓存短于文案会把两个前缀相同的长文案误判为「没变」而**漏刷新**。
  本会话已被这个坑咬过三次，且**编译器只对字面量报警**，运行时拼接的文案抓不到。
- **总览页不滚动**，一屏放下。改版后要重新核实行数放得下。
- 每步改完**编译**，攒够一个阶段再刷机（减少刷机次数）。

## 六、结论：四页已完成（2026-09-18）

| 目标项 | 落地方式 |
|---|---|
| 金属 bezel | 4 条**覆盖式**边缘带（不改内容区，见「四处不同的风险」） |
| 带标题边框盒 | 总览读数盒与列表面板、驾驶舱天气卡与指标卡、设备页四张卡 |
| LED 状态灯 | 外壳 PWR/NET；服务端圆点并入 ui_led |
| 琥珀磷光读数 | 34px 纯数字字体 + COL_ACCENT |
| 点线引导符 | **降级为 1px 暗实线**（LVGL 无虚线） |
| 磷光辉光 | **放弃**（LVGL 无文字发光） |

### ⭐ 最重要的经验：同一改动，四页的代价完全不同

「把卡片标题改成骑在边框上」这一件事，四页的代价分别是：

| 页面 | 情况 | 代价 |
|---|---|---|
| 总览页 | flex 流 + **零余量** | 必须重算行数，去掉页面标题才腾出 13px |
| 驾驶舱页 | 内容全用 lv_obj_align 绝对定位 | **高度都不用改**，标题骑进已有的 14px 行距 |
| 设备页 | page_root **本身可滚动** | 溢出由滚动承担，只需给第一张卡加 pad_top |
| 服务端 | 卡片是**内容行、无独立标题** | **不需要改**，强行套用反而是错的 |

→ **不要拿一页的结论套另一页。先读实现、再把布局常量逐个加起来算账。**

### 另一条经验：预留了资源却没用上

总览页曾出现「lists_row 已按 13px 预留标题位，但面板仍在盒内画 kicker」——
同一件事付了两次空间，导致列表区**零余量**、最后一行随时可能被切。
这类浪费**静态读代码看不出来**，是把常量加起来核算才发现的。

### 服务端页为何不改

其可变内容全在**可滚动**的 host_list 里（溢出由滚动承担），
且卡片是内容行 —— 主机名本身就是行内容，没有独立的卡标题可以骑到边框上。

## 七、遗留与风险

- ⚠️ **所有布局改动均未经目视确认**。每轮都编译+刷入+抓启动日志（无 abort/panic），
  但「标题是否被裁、读数是否够亮、最后一行是否完整」这几类问题
  **只有真人看屏幕才能确认**。
- 导航圆点仍为自绘圆形（与 ui_led 不同）—— 它是页面指示器而非状态灯，
  语义不同，故保留。
- 若回退：`git revert -m 1 <merge-commit>` 或直接丢弃 `ui-redesign` 分支。
